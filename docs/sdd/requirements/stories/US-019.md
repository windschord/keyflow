# US-019: WindowsのMicrosoft Store配布（スマート アプリ コントロール対策）

## ユーザーストーリー

**私は** Windows 11のアプリ利用者として
**〜したい** ブロックされずにインストールできる正規の入手経路でkeyflowを導入したい
**なぜなら** スマート アプリ コントロール（SAC）が有効な環境では、未署名の`.exe`は
発行元を確認できないものとしてブロックされ、起動できないから

## 背景（本ストーリー追加の経緯）

2026-08-10、利用者から `keyflow-Setup-0.1.0-x64.exe` がSACにブロックされ実行できない
との報告があった。原因は成果物が未署名であることで、US-018で追加したportable版も
同じ理由でブロックされるため配布形態の変更では回避できない。

SACはSmartScreenと異なり「詳細情報 → 実行」に相当する回避手段を提供しない。
利用者側でSACを無効化する方法はあるが、一度オフにするとWindowsの再インストールまで
再度オンにできないため、利用者へ案内する回避策としては採用できない。

コード署名による解決も検討したが、以下の理由で採用しなかった。

- Azure Trusted Signing（月額約$9.99）: **個人開発者の本人確認が米国・カナダ在住者に
  限定**されており、日本在住の個人開発者は本人確認を完了できない（組織としてなら日本も対象）
- OV/EV証明書: 年間数万円の継続費用が必要

Microsoft Storeで配布されるパッケージはMicrosoftが署名するためSACの対象外となり、
証明書の購入・更新も不要になる（開発者アカウント登録料$19の1回払いのみ）。

## 受入基準（EARS記法）

### 機能要件

- **REQ-019-001**: システムはWindows向けリリース成果物として、Microsoft Storeへ提出可能な
  MSIX/AppXパッケージを生成しなければならない
- **REQ-019-002**: 生成するMSIXパッケージは、Partner Centerで予約した識別情報
  （`Identity/Name`・`Identity/Publisher`・`Properties/PublisherDisplayName`）を
  埋め込まなければならない。これらはStoreの登録値と完全に一致しなければならない
- **REQ-019-003**: システムはWindows向けMSIXパッケージをx64とarm64の2アーキテクチャで
  提供しなければならない（US-018のREQ-018-001を引き継ぐ）
- **REQ-019-004**: システムはWindows向けの`.exe`（NSISインストーラー版・portable版）を
  GitHub Releaseへ添付してはならない。SACにブロックされ利用者が実行できないため、
  実行不能な成果物を配布経路へ露出させない
- **REQ-019-005**: MSIXパッケージはローカルで署名してはならない。署名はMicrosoft Storeが
  配布時に行うため、ビルド成果物は未署名のままPartner Centerへ提出する
- **REQ-019-006**: MSIXパッケージはGitHub Releaseへ添付せず、ワークフロー成果物としてのみ
  保管しなければならない。未署名のAppXは利用者がそのままインストールできず、
  Partner Centerへのアップロード専用の中間成果物であるため
- **REQ-019-007**: MSIXのタイル画像（StoreLogo・Square44x44Logo・Square150x150Logo・
  Wide310x150Logo）は、既存のマスターSVG（`resources/icon.svg`）から生成し、
  アプリアイコンと同一の図案でなければならない

### 対象外（本ストーリーのスコープ外）

- macOSの配布形態変更（現行のdmg/zip×x64/arm64をGitHub Releaseで維持する）
- macOSのコード署名・公証（引き続き未対応。初回起動時のGatekeeper警告は既知の制約）
- Partner Centerへの提出自動化（`msstore` CLIによるCI提出。現時点では成果物を
  ダウンロードして手動アップロードする運用とする）
- 自動アップデート（NFR-C-007。Store配布では将来的にStore側の更新機構を利用できる）
- Storeを利用できない利用者向けの代替配布経路（SignPath Foundation等による署名は
  将来の選択肢として残すが、本ストーリーでは扱わない）

- 該当なし（配布・ビルド設定の変更のみ）

## 備考

- AppXのビルドはWindows上でのみ可能である（app-builder-libの`AppxTarget`が
  Windows以外でエラーを送出する）。したがってCIは`windows-latest`ランナーで実行し、
  ローカルmacOS/Linuxでは検証できない
- Partner Centerの登録値は秘密情報ではない。配布されるMSIXの`AppxManifest.xml`に
  平文で埋め込まれ、誰でも参照できるため、`electron-builder.yml`へ直接記載してよい
- Store提出後の審査には通常1〜3日を要する。Storeでの公開が完了するまでの間、
  Windows利用者の入手経路は既存のv0.1.0リリース（未署名`.exe`）のみとなる
